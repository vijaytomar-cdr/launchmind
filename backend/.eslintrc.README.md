# Backend ESLint configuration

The backend previously had **no config of its own**, so `eslint src` inherited the
root Next.js config. That caused two failures:

1. It looked for a Next `pages/` directory that a Fastify service will never have.
2. It did not load the TypeScript plugin, so `@typescript-eslint/no-explicit-any`
   was not a *defined* rule — which made an `eslint-disable-next-line` naming that
   rule an error in itself (the Step 8 finding).

`.eslintrc.json` fixes this by making the rule **real and enforced** rather than by
disabling linting. `no-explicit-any` is an error in `src/` and a warning in `tests/`,
where stubbing broken provider clients legitimately needs loose shapes.
